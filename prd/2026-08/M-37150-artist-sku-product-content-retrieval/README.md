## 业务背景和价值

美工版 AI 生图最初主要服务新品开发。新品摄影图当时保存在本地共享盘，未统一上传到阿里云 OSS，因此美工版当前不会根据系统 SKU 自动取得参考图，新增和批量任务均依赖美工人工上传图片。

随着美工开始承担部分老品优化，老品在产品库中已经存在可直接使用的商品资料和图片。美工版当前通过系统 SKU 取得商品标题、类目、尺寸和卖点的具体数据源及实现方式也未形成统一、可核对的口径，出现数据问题时不利于明确排查链路。

产品库现已提供按系统 SKU 批量查询商品信息和产品图片的接口。本需求统一规定美工版只通过指定产品库接口取得商品中文标题、产品库统一类目、商品尺寸、中文核心卖点和白底参考图，使单个新增与批量导入使用同一套可追踪、可验收的数据口径；同时让已有产品库图片的老品可以自动带入参考图，减少人工上传。对于暂时没有产品库图片的新品，仍允许通过现有人工完善流程继续处理，不在本期增加新品图片数据源。

## 需求概述

1. 美工版新增任务抽屉和批量导入系统 SKU 统一调用 `GetProductsV2`，取得产品库商品中文标题、产品库统一类目、商品尺寸和中文核心卖点。
2. 两个入口统一调用 `ProductImage/GetList`，按系统 SKU 取得产品库白底参考图；有图时自动回填，无图时按单个或批量入口的既定完整性规则由业务人工补充。
3. 批量导入继续限制最多 50 个非空原始输入行；去重后的有效 SKU 合并批量查询，不再逐个 SKU 重复调用接口，并预留按两个接口各自单批上限自动分组的通用能力。
4. 单个新增只有资料完整后才能保存或提交；批量导入在产品对象存在时，根据商品图文信息、参考图和现有模型配置的完整性创建“待提交”或“待完善”任务。
5. 批量导入弹窗提示文案同步调整，使其同时适用于自动取得参考图的老品和仍需人工补图的新品。

本需求属于现有取数和任务完整性规则优化，仅修改现有新增任务抽屉、批量导入系统 SKU 链路及一处提示文案，不新增页面、字段或复杂交互，不需要单独制作 HTML 原型。

## 功能需求

### 1. 统一商品文本信息数据源

美工版新增任务和批量导入必须通过以下产品库接口取得商品文本信息，不得继续直接查询数据库表、调用其他老接口，或在指定接口无数据、字段为空及调用失败时改用其他数据源兜底。

- 接口：`POST http://erpapi.zhcxkj.com/Erp/Products/GetProductsV2`
- 固定参数：`input.customerId = 1`，数字类型。
- 查询参数：`input.skus`，字符串数组。
- 稳定关联键：响应每个产品对象的 `data[].sku`。

脱敏请求示例：

```json
{
  "input": {
    "customerId": 1,
    "skus": ["8154637", "22062564"]
  }
}
```

请求和响应数组顺序不保证一致，系统必须按每个响应对象内的 `sku` 与请求 SKU 精确关联，不得按数组下标、返回位置或请求顺序关联。

### 2. 商品文本信息字段映射

| 页面字段 | 产品库响应字段 | 取值和展示规则 |
|---|---|---|
| 商品中文标题 | `data[].productNameCN` | 取产品库中文标题；去除字段值前后空白后回填，不使用 `productName` 或其他标题字段 |
| 类目 | `data[].browsePathByName` | 取产品库统一类目名称完整字符串；去除前后空白，不拆分、不翻译，保留中英文括号及原有路径结构 |
| 商品尺寸-长 | `data[].length` | 顶层字段，源数据单位为厘米；不使用包装、箱规或其他尺寸字段 |
| 商品尺寸-宽 | `data[].width` | 顶层字段，源数据单位为厘米；不使用包装、箱规或其他尺寸字段 |
| 商品尺寸-高 | `data[].height` | 顶层字段，源数据单位为厘米；不使用包装、箱规或其他尺寸字段 |
| 中文核心卖点 | `data[].highLightsOfFirst` 至 `data[].highLightsOfFifth` | 按第一至第五的固定顺序读取；逐项去除前后空白并跳过无效项，每条有效卖点单独一行回填，不增加序号、圆点或其他前缀，不使用英文卖点字段 |

美工版页面字段名称继续使用“商品中文标题”“类目”“商品尺寸”“中文核心卖点”。其中“中文核心卖点”与运营版的“五点描述”名称不同，本需求不得将美工版字段名称改成“五点描述”。

页面长、宽、高输入框继续显示固定单位 `CM`，不调整现有页面样式；调用生图接口时，组装字符串中的尺寸单位按第 9 节规则固定使用小写 `cm`。

产品对象中的 `deleteStatus`、`productState`、`checkStatus`、`editStatus`、`onlineStatus` 等状态字段不参与本次过滤、排序或结果有效性判断。只要接口返回当前 SKU 的唯一产品对象，就继续读取本需求目标字段并判断资料完整性。

### 3. 商品文本信息有效性和异常数据

各字段按以下规则判断：

1. 标题：`productNameCN` 去除前后空白后至少包含 1 个字符。
2. 类目：`browsePathByName` 去除前后空白后至少包含 1 个字符。
3. 尺寸：`length`、`width`、`height` 均能解析为大于 0 的有效数值时，商品尺寸才完整；任一字段缺失、为 `null`、空字符串、纯空白、0、负数或非法值时，尺寸整体判定为不完整。有效的单项尺寸按接口返回值回填，无效单项保持为空，不得展示或保存为 `0`、负数、`null`、非法值，也不能用其他尺寸字段补齐。
4. 中文核心卖点：五个 `highLights` 字段按固定顺序逐项处理，字段缺失、为 `null`、空字符串或纯空白时跳过；至少存在 1 条有效卖点即判定卖点完整，不要求五个字段全部有值。
5. 某个 SKU 有唯一产品对象，但以上任一必填资料不完整时，不得将其误判为“未查询到产品”。单个新增回填已有内容并等待人工补齐；批量导入仍创建任务并标记为“待完善”。

接口响应按以下异常边界处理：

- 接口无 HTTP 成功响应，或 HTTP 成功但业务状态表示失败时，本次商品信息查询失败，不得只依据 HTTP 状态判断成功。
- 接口业务状态成功但 `data` 缺失、为 `null` 或不是数组时，按接口响应结构异常处理并记录可定位日志。单个查询失败；批量当前商品信息分组内所有 SKU 均导入失败且不创建任务，其他成功分组继续处理。
- `data` 为空数组时，按本次请求的所有 SKU 均“未查询到产品”处理；单个查询失败，批量当前分组内各行均导入失败且不创建任务，其他成功分组继续处理。
- `data` 为数组但完全没有某个请求 SKU 的产品对象时，该 SKU 为“未查询到产品”。单个查询失败；批量仅该行导入失败且不创建任务，其他行继续处理。
- 响应中出现未包含在本次请求中的 SKU 时，忽略该对象并记录可定位日志，不得关联到相邻请求项。
- 同一个请求 SKU 返回多个产品对象时，该 SKU 按异常数据处理并记录可定位日志，不得任意取第一条。单个查询失败；批量仅该行导入失败且不创建任务。
- 不得因某个产品对象字段不完整而改查其他数据源，也不得在标题、类目或卖点为空时使用 Listing 同类字段兜底。

### 4. 统一白底参考图数据源

美工版新增任务和批量导入统一通过以下产品库接口查询当前系统 SKU 的白底参考图：

- 接口：`POST http://erpapi.zhcxkj.com/Product/ProductImage/GetList`
- 固定参数：`isWhiteBackGround = 1`，数字类型。
- 查询参数：`skus`，字符串数组。
- 稳定关联键：响应图片对象的 `data[].sku`。

脱敏请求示例：

```json
{
  "isWhiteBackGround": 1,
  "skus": ["22062564", "23240511"]
}
```

图片接口返回扁平图片列表，同一个 SKU 可返回多条图片记录；没有白底图的 SKU 不保证返回空占位对象。系统须按每条图片对象的 `sku` 分组，并通过请求 SKU 与响应 SKU 的差集识别无图片项，不得按数组位置关联。

每个 SKU 的自动参考图按以下规则处理：

1. 保持接口对该 SKU 的图片原始返回顺序。
2. 只读取 `imageUrl`，先去除前后空白，跳过字段缺失、`null`、空字符串或纯空白的记录。
3. 按处理后的完整 URL 精确去重，相同 URL 只保留首次出现的一条。
4. 从有效且去重后的结果中依次取前 5 张，作为自动参考图。
5. 本期不使用 `cosImageUrl`，也不根据 `isCover`、`isSpareCover`、`isHand`、`isScene` 等其他图片属性增加筛选、分类或排序。
6. 取数阶段不逐张下载或访问图片 URL 验证可用性；后续图片读取异常沿用现有处理。
7. 自动取得与人工上传的参考图合计仍为 1～5 张，不要求补足 5 张，也不得超过现有上限。

请求入参 `isWhiteBackGround` 固定使用数字 `1`。响应图片对象中如存在同名属性，该属性属于响应字段，不用于本期二次筛选；不得因请求与响应中的同名字段类型不同而改变本需求请求类型。

接口业务状态成功且 `data` 为空数组时，按本次请求没有自动参考图处理，不影响已取得的商品文本信息。接口业务状态成功但 `data` 缺失、为 `null` 或不是数组时，同样按没有自动参考图继续处理，同时记录接口响应结构异常日志。图片对象的 `sku` 缺失、为 `null`、空字符串、纯空白或不属于本次请求时，忽略该对象并记录可定位日志，不得关联到相邻 SKU，也不得将单条异常扩大为整批失败。

图片接口失败或某个 SKU 无有效白底图时，不影响该 SKU 已取得的商品文本信息：单个新增的自动参考图保持为空，业务手动上传至少 1 张后才能保存或提交；批量导入在产品对象存在时创建“待完善”任务，其他 SKU 继续处理。

### 5. 单个新增任务抽屉

1. 用户输入系统 SKU 后点击“查询”，系统先去除输入值首尾空白；处理后为空时沿用现有必填校验，不调用接口。非空 SKU 按完整字符串查询，不转换为数字、不改变前导零或大小写，再调用本需求指定的两个接口并按 SKU 聚合商品文本信息和白底参考图。
2. 查询到唯一产品对象时，回填所有有效商品资料；字段不完整或没有自动参考图时允许用户人工补充，但补齐前不能“保存为待提交”或“保存并提交生图”，也不会先生成“待完善”任务。
3. 单个新增允许保存或提交前，必须同时满足：商品中文标题有效、类目有效、长宽高均有效、至少有 1 条有效中文核心卖点、最终组装的商品文本信息不超过 2500 个字符、自动与人工参考图合计为 1～5 张，并且模型与数量等现有必填配置均满足既有规则。
4. 未查询到产品、商品信息接口失败或返回异常产品对象时，查询失败，不使用其他数据源补数。
5. 新增抽屉已有商品资料后再次查询，继续沿用现有覆盖确认弹窗，文案为“已有商品信息是否覆盖？”：取消后不改变现有资料；确认且查询成功后，以新查询结果覆盖原商品文本信息和参考图，包括用户已人工修改的内容；确认后查询失败或未查询到产品时，现有已回填资料保持不变。

编辑任务抽屉中的系统 SKU 继续置灰且不展示查询按钮。编辑时只读取任务已经保存的商品资料和参考图，不重新调用本需求两个接口；业务可按现有能力人工完善商品文本信息、参考图和其他可编辑字段。

本期不处理项：新增抽屉当前存在“用户将已成功查询的 SKU A 改为 SKU B，B 查询失败后，输入框和后续保存 SKU 为 B，但下方仍保留 A 的旧资料”的现状问题。该问题与运营版存在共性，本期不调整其清空、回退或保存拦截逻辑，后续另行统一优化，不作为 M-37150 的开发和验收范围。

### 6. 批量导入输入预处理和去重

批量导入系统 SKU 继续使用每行一个 SKU 的现有输入方式，并严格按以下顺序处理：

1. 按行拆分用户输入。
2. 去除每行 SKU 的首尾空白字符。
3. 忽略处理后的纯空白行；空白行不占 50 行额度。
4. 对剩余非空原始行计数，超过 50 行时整批校验不通过，不执行导入，也不发起商品信息或图片空请求。50 行额度在去重前计算，因此重复 SKU 仍占额度。
5. 在不超过 50 行后，按去除首尾空白后的完整 SKU 字符串精确去重；重复值只保留首次出现的一行及其原始顺序，最多创建一个任务。
6. SKU 全程按字符串处理，不转换为数字，不改变前导零，不转换大小写，也不增加“只能输入纯数字”等本期未确认的格式限制。
7. 没有任何有效 SKU 时不调用两个上游接口，沿用现有空输入校验，不创建任务。

示例：输入 ` 00123 `、`00123`、空白行、`ABC01` 时，非空原始行数为 3，去重后按顺序查询 `00123`、`ABC01`，最多创建 2 个任务。

### 7. 批量接口调用、分组和结果关联

批量导入对去重后的有效 SKU 分别调用商品信息接口和图片接口：

| 接口 | 已确认单批上限 | 当前最多 50 行时的调用规则 | 通用扩展规则 |
|---|---:|---|---|
| `GetProductsV2` | 500 个 SKU | 全部有效 SKU 合并为最多 1 次调用 | 超过 500 时按每组最多 500 个 SKU 顺序分组 |
| `ProductImage/GetList` | 100 个 SKU | 全部有效 SKU 合并为最多 1 次调用 | 超过 100 时按每组最多 100 个 SKU 顺序分组 |

以上上限已通过真实接口响应确认：`GetProductsV2` 传 500 个 SKU 成功，传 1000 个时业务响应提示“sku一次最多支持500个”；`ProductImage/GetList` 传 100 个 SKU 成功，传 101 个时业务响应提示“参数Skus数量超过100”。本需求仍保留页面最多 50 行限制，因此正常页面操作不会触发分组；研发须将调用能力实现为可按各接口自身上限分组的通用逻辑，方便后续将页面上限扩展到 100 或更高时复用。

两个接口之间的调用先后、是否并行及后端聚合方式由研发结合现有架构确定，但不得改变本需求的数据源、关联、状态和失败结果。同一接口未来出现多个分组时按顺序调用，不启用未经接口负责人确认和专项验证的瞬时并发；不同接口不得照搬同一个分组大小。

所有请求和响应均按每个对象内的 `sku` 稳定关联，不能依赖数组下标。批量各行独立聚合商品文本信息与图片，任何一行的返回、缺失或失败结果不得串用到其他行。

分组失败时按以下规则隔离：

- 某个商品信息分组调用失败或业务状态失败时，该分组内所有 SKU 导入失败且不创建任务，其他成功分组继续处理。
- 某个图片分组调用失败时，该分组内已经取得唯一产品对象的 SKU 仍创建“待完善”任务；其他图片分组继续处理。
- 不新增自动重试、缓存或其他数据源降级。若底层已有网络重试，须保持请求 SKU、数据源、分组边界和最终业务结果不变，不能无限重试或把单组失败扩大为整批失败。

### 8. 批量任务创建和状态判断

批量导入以“是否取得当前 SKU 的唯一产品对象”作为创建任务的主链路门槛：

| 场景 | 当前 SKU 结果 | 是否影响其他 SKU |
|---|---|---|
| 取得唯一产品对象，全部必填资料完整 | 创建“待提交”任务 | 不影响 |
| 取得唯一产品对象，但任一必填资料不完整 | 创建“待完善”任务 | 不影响 |
| 完全没有返回产品对象 | 当前行导入失败，不创建任务 | 不影响 |
| 同一 SKU 返回多个产品对象 | 当前行导入失败，不创建任务并记录异常 | 不影响 |
| 商品信息接口对应分组失败 | 当前组各行导入失败，不创建任务 | 其他成功组继续 |

批量任务满足以下全部条件时为“待提交”，任一条件不满足时为“待完善”：

1. 商品中文标题有效。
2. 类目有效。
3. 长、宽、高三个尺寸均为大于 0 的有效数值。
4. 五个中文核心卖点字段中至少存在 1 条有效内容。
5. 最终组装的商品文本信息不超过 2500 个字符。
6. 自动取得与人工上传的参考图合计为 1～5 张；批量导入弹窗没有人工上传参考图入口，首次导入时按本次自动取得的参考图数量判断。
7. 模型与数量等配置已按现有必填规则完善。

“待完善”任务后续由业务进入编辑抽屉补齐缺失内容，全部满足既有保存校验后转为“待提交”。本需求不根据产品类型显式判断“老品”或“新品”：有完整产品资料和图片的 SKU 自然可以进入“待提交”，没有产品库图片或其他资料不完整的 SKU 进入“待完善”。

### 9. 商品文本信息组装和 2500 字限制

商品中文标题、类目、尺寸和中文核心卖点在调用生图接口时，以当前任务最终保存或提交的字段值统一组装为一段商品文本信息：单个新增使用当前新增任务抽屉中的最终字段值，批量任务使用导入后已保存并经业务人工完善的当前任务字段值。接口自动取数只作为初始值，业务后续人工修改的内容是最终保存、提交和组装依据。不同生图服务实际承载该内容的请求字段名称或字段路径继续沿用各自接口现状，不属于本需求统一范围；各调用方必须使用本节相同的组装结果。

固定组装格式：

```text
【标题】: {productNameCN}；【类目】: {browsePathByName}；【尺寸】: 长{length} X 宽{width} X 高{height} cm；【卖点】: {有效卖点1}、{有效卖点2}、...
```

组装规则：

1. 字段顺序固定为标题、类目、尺寸、卖点。
2. 字段名前缀固定为 `【标题】`、`【类目】`、`【尺寸】`、`【卖点】`，每个前缀后使用英文半角冒号和 1 个空格，即 `: `。
3. 字段之间使用中文全角分号 `；`，最后一个字段末尾不额外添加分号。
4. 尺寸固定为 `长{length} X 宽{width} X 高{height} cm`；`X` 为大写英文字母且两侧各 1 个空格，`cm` 为小写且前面保留 1 个空格。
5. 尺寸为整数值时不显示无意义的 `.0`；小数保留实际有效小数位并去除末尾多余的 0，不使用科学计数法，不进行单位换算。
6. 接口自动回填时，每条有效中文核心卖点单独一行、不加序号。业务人工修改后，以中文核心卖点文本框当前内容为准；组装前将 Windows、Linux 和旧式 Mac 换行统一为单一换行符，再按行拆分、逐行去除首尾空白并跳过空白行，按剩余行的原始顺序使用中文顿号 `、` 连接。每行内部已有文字和标点保持不变，最终组装字符串不保留卖点换行。自动回填、人工编辑后的卖点完整性均按同一处理结果判断，至少剩余 1 行有效内容即为完整。
7. 2500 字限制按最终组装字符串的 Unicode 字符个数统计，标题前缀、类目前缀、尺寸前缀、卖点前缀、字段值、空格、标点、尺寸单位和连接符均计入；不按字节数统计。
8. 页面字数提示、保存校验、批量状态判断和最终生图请求必须使用同一组装结果和同一计数方法，不得分别拼接或出现计数不一致。
9. 超过 2500 个字符时不得静默截断。单个新增阻止保存和提交，由业务修改至限制内；批量导入创建“待完善”任务。

SKU `14033073` 的组装结果示例：

```text
【标题】: 五金家用手提式电工多功能维修车载盒工具箱（黑色10寸）（配件颜色随机）；【类目】: Tools & Home Improvement(家居装修)>>Power & Hand Tools(家装工具)>>Tool Organizers(工具收纳)>>Tool Boxes(工具箱)；【尺寸】: 长31 X 宽16 X 高12 cm；【卖点】: 手提式设计便于随身携带，解决车载，户外或临时维修时工具散乱难取用的问题，适用于自驾途中电路检修或家庭突发线路故障、内置多格分层结构与弹性固定带，防止螺丝刀，钳子等工具在移动中相互碰撞磨损，满足颠簸路况下车载工具稳定收纳需求、兼容常用电工配件如测电笔，剥线钳，绝缘胶带等，解决家庭日常灯具更换，插座安装，小家电接线等基础维修工具不全问题、加厚PP材质箱体抗压耐摔，应对工地搬运，后备箱堆放及频繁开合使用场景，保障工具长期有序存放不散乱、盒盖内侧集成磁吸条与卡槽，可快速吸附金属小零件并固定常用工具，避免维修中螺丝，垫片掉落丢失，提升现场作业效率
```

### 10. 批量导入提示文案

美工版“批量导入系统 SKU”弹窗底部提示文案由：

```text
提示: 导入后任务状态为“待完善”，请在列表补充参考图后提交。
```

调整为：

```text
提示: 导入后任务状态若为“待完善”，请编辑补充商品图文信息后提交。
```

以上新文案的文字、空格和标点按原样展示。除该提示外，本期不调整批量弹窗的字段、按钮、布局、输入方式和其他提示。

### 11. 数据保存、历史兼容和权限

- 本需求只影响上线后的新增任务查询和批量导入，不对历史任务执行专项回查、补数、SQL 更新或批量修复。
- 查询或导入取得的商品资料和参考图继续按现有任务数据保存。上游数据后续变化不会自动改写已保存任务。
- 编辑任务不重新查询上游接口，继续展示任务当前保存的数据。
- 现有任务状态名称、模型与数量配置、人工编辑、人工上传参考图、保存、提交生图及后续审核推送流程保持不变。
- 本需求只作用于美工版对应入口；运营版 M-37095 店铺 ASIN 的 Listing、五点描述、产品库尺寸和参考图数据分工保持不变，不得将美工版“全部取产品库”的规则套用到运营版。
- 现有账号、角色、数据可见范围和操作权限不变。查询结果只用于当前用户有权创建或编辑的任务，不得借批量聚合扩大任务或数据访问范围。

### 12. 后续图片能力预留边界

本期固定传 `isWhiteBackGround = 1`，只自动取得产品库白底图。研发设计图片查询和聚合逻辑时，应将“调用图片接口”“按图片属性分类”“选择图片类型和数量策略”解耦，避免把当前白底图规则固化为永久不可扩展的实现。

以下均为后续独立需求方向，不属于本期开发和验收范围：

- 美工版和运营版按图片属性自动组合参考图，例如 3 张白底图、1 张场景图和 1 张手持图；届时可能只传 SKU 查询全部图片，再依据真实响应属性分类。
- 业务点击“选图”后按当前 SKU 实时查询产品图片接口，并在弹窗中按图片属性分类展示，供业务选择。
- 新品摄影图前置上传至阿里云 OSS 后，由下游提供独立新品图片接口。届时可另行评估“先查产品库图片，未取得时再查新品图片接口，仍无图则保持为空”的链路。

产品图片接口单批 100 个 SKU 的已确认上限仅适用于本期 `isWhiteBackGround = 1` 的请求方式。未来取消该参数或查询全部图片类型时，须重新确认实际请求、响应结构、单批上限、分类字段和选图优先级，不能直接沿用本期结论。

## 风险描述

1. 商品信息和白底参考图依赖产品库接口及源数据完整性。本期不设置其他数据源兜底，因此上游字段为空、无图片或接口失败会直接体现为单个新增需人工补齐、批量任务“待完善”或当前行导入失败。
2. 新品摄影图尚未通过可用接口提供时，新品任务仍可能没有自动参考图，需要美工从现有共享盘人工选择并上传；本需求只解决已有产品库图片的老品自动取图场景。
3. 两个接口的 500 和 100 单批上限分别适用于当前已验证请求方式；后续页面扩量、参数变化或全类型图片查询仍需结合正式接口说明和目标环境重新评估。

## 验收标准

### 1. 商品信息接口和字段

1. 新增任务和批量导入均只通过 `GetProductsV2` 查询本需求商品文本信息，请求固定携带数字类型 `customerId = 1`，SKU 保持字符串；代码路径中不存在数据库直查、老接口或其他文本数据源兜底。
2. 标题、类目、长宽高和中文核心卖点分别从 `productNameCN`、`browsePathByName`、顶层 `length/width/height`、五个 `highLights` 字段读取，页面名称、类目完整路径和字段顺序符合本文规则。
3. 产品状态字段不参与过滤。返回唯一产品对象但字段不完整时，单个入口回填已有字段并阻止保存或提交，批量入口创建“待完善”任务。
4. 请求与响应顺序不一致时仍能按 `data[].sku` 正确关联。缺少某 SKU 对象、返回请求外 SKU 或同一 SKU 返回多个对象时，处理结果和日志符合本文异常边界，不发生错行关联。
5. 长、宽、高中部分字段有效、部分字段为 0 或其他无效值时，仅回填有效单项，无效单项保持为空，尺寸整体判定为不完整；不得展示或保存无效尺寸，也不得用包装、箱规等其他尺寸补齐。
6. 商品信息接口业务成功但 `data` 缺失、为 `null` 或非数组时，按响应结构异常记录日志并执行对应单个或分组失败结果；`data` 为空数组时，按当前请求所有 SKU 均未查询到产品处理。两类场景均不得错误创建任务或影响其他成功分组。

### 2. 白底参考图

1. 两个入口均通过 `ProductImage/GetList` 查询参考图，请求固定携带数字类型 `isWhiteBackGround = 1`。
2. 同一 SKU 返回多条图片时，系统按该 SKU 原始顺序处理 `imageUrl`，跳过空值、完整 URL 精确去重并最多取前 5 张；不使用 `cosImageUrl` 或其他属性重新排序。
3. 图片响应没有为某 SKU 返回占位对象时，系统能识别该 SKU 无图，不会取到相邻 SKU 图片。
4. 图片接口失败或当前 SKU 无图时，商品文本信息仍正常回填；单个入口须人工上传至少 1 张后才能保存或提交，批量在产品对象存在时创建“待完善”任务，其他 SKU 不受影响。
5. 图片接口业务成功且 `data` 为空数组时按正常无自动参考图处理；`data` 缺失、为 `null` 或非数组时仍按无自动参考图继续，但须记录响应结构异常日志。图片对象缺少有效请求内 `sku` 时忽略并记录日志，不发生错行关联或整批失败。

### 3. 单个新增和编辑

1. 单个查询先去除 SKU 首尾空白，空值不发起接口请求；非空 SKU 保持完整字符串，不转数字、不丢失前导零、不转换大小写。只有标题、类目、三项尺寸、至少一条中文核心卖点、2500 字限制、1～5 张参考图和现有模型配置全部满足时，才能保存为待提交或提交生图；资料不完整时不创建“待完善”任务。
2. 已有资料时再次查询会展示现有覆盖确认弹窗；取消、成功覆盖和查询失败保留资料分别符合本文规则。
3. 编辑抽屉的系统 SKU 置灰且没有查询按钮，打开和保存编辑任务均不重新调用两个上游接口。

### 4. 批量输入、调用和状态

1. 空白行不占 50 行额度，重复 SKU 在去重前占额度；超过 50 个非空原始行时整批不导入。去除每行首尾空白后按完整字符串精确去重，只保留首次出现的 SKU 和顺序。
2. SKU 不转数字、不丢失前导零、不转换大小写。50 行以内的去重有效 SKU 分别合并为商品信息接口和图片接口最多各 1 次批量调用，不逐个 SKU 调用，也不发起空请求。
3. 批量结果全部按对象内 `sku` 关联。重复输入最多创建一个任务，任一 SKU 的字段、图片或失败结果不会串到其他任务。
4. 产品对象存在且全部必填条件完整时创建“待提交”；产品对象存在但任一条件不完整时创建“待完善”；没有产品对象、同一 SKU 多对象或商品信息分组失败时当前行不创建任务，其他行继续。
5. 通过单元测试、模拟接口响应或可审计的请求分组日志验证通用分组能力：商品信息每组不超过 500 个 SKU，图片每组不超过 100 个 SKU，各接口独立分组并按稳定键聚合；当前页面仍保持最多 50 行。本项不要求再次向正式接口发送超限请求探测容量。
6. 批量导入弹窗底部准确展示“提示: 导入后任务状态若为“待完善”，请编辑补充商品图文信息后提交。”，其他布局和交互不变。

### 5. 文本组装、兼容和隔离

1. SKU `14033073` 按本文样例组装时，字段顺序、前缀、半角冒号及空格、中文分号、尺寸格式、整数去 `.0` 和卖点顿号连接均一致；页面尺寸单位保持 `CM`，最终组装字符串使用小写 `cm`。
2. 自动回填的有效卖点在页面逐条换行且无序号；人工编辑后混用不同换行符、空白行和行首尾空白时，系统按本文规则标准化并以当前非空行使用 `、` 连接。单个新增使用当前抽屉最终值，批量任务使用当前已保存并经业务完善的任务值；页面计数、保存校验、批量状态判断和不同生图接口请求使用同一最终字符串及 Unicode 字符计数，超过 2500 个字符时不静默截断。
3. 历史任务不回查、不补数，编辑历史任务不自动变化；运营版 M-37095 取数逻辑不受影响。
4. 使用不同美工账号分别验证新增、批量和编辑入口，任务创建、查看和编辑继续受现有账号、角色及数据权限约束，不发生跨账号任务串用；既有模型配置、人工上传、审核和推送流程回归正常。
