## 业务背景和价值

美工版、运营版 AI 生图均已支持标准普通A+图类型和“生成图片语言”字段。美工版标准普通A+图审核通过后进入产品库“A+图片”，不进入 A+ 管理；运营版继续沿用现有 A+ 管理链路。两端现有任务创建、审核、展示和推送流程无需重新建设。

多模型能力上线时，因阿里绘蛙尚未支持普通A+图，系统已在“模型 × 图片类型”配置中预留对应位置，通过不配置或将 `aplus` 配置为 `0` 保持不可用。现阿里绘蛙商品套图建任务接口已新增普通A+图能力，查询结果接口也已提供普通A+图类型枚举，本期需补齐系统与阿里绘蛙之间的参数和结果类型映射，使两端后续仅调整配置即可开放阿里绘蛙标准普通A+图。

本期接入可以在不重复建设页面和业务流程的前提下扩充标普A+可用模型，并将美工、运营不同开放时间收敛为配置管理，避免后续业务开放时再次开发接口能力。

本期不新增页面、图片类型、语言选项或交互，不需要单独制作 HTML 原型。

## 需求概述

1. 美工版、运营版共用的阿里绘蛙商品套图建任务链路新增标准普通A+图张数传参：任务中的阿里绘蛙标普A+计划张数映射至 `aplusNum`。
2. 阿里绘蛙标普A+读取任务已保存的“生成图片语言”，复用现有阿里绘蛙卖点图语言编码映射并传入 `outputLanguage`，不再固定传 `en`。
3. 查询结果中将 `imageResults[].imageType=7` 识别为标准普通A+图，并继续沿用现有结果关联、图片落库、审核和推送链路。
4. 本期不传 `aplusScenes`；A+参考图能力留待二期独立规划。
5. 代码能力同时覆盖美工版和运营版。美工版初始化配置值和用户范围待业务后续提供表格，运营版本期保持未配置或配置为 `0`，后续均只通过配置开放。
6. 美工版、运营版任务抽屉、批量导入和批量修改中的“模型与数量配置”，同步将标普A+行问号提示中的支持模型更新为阿里绘蛙和LinkFox。

## 功能需求

### 1. 影响入口与直接改造范围

后端直接改造点为美工版、运营版共用的阿里绘蛙商品套图建任务及结果解析链路，各业务入口不分别开发一套接口逻辑。前端直接改造点为现有“模型与数量配置”中标普A+行的问号提示文案。

本期沿用现有阿里绘蛙商品套图建任务和查询结果接口，不切换接口地址，仅补齐 `aplusNum`、标普A+场景的 `outputLanguage` 及 `imageType=7` 映射。

以下所有会创建新阿里绘蛙任务的入口统一覆盖：

| 业务端 | 入口 |
|---|---|
| 美工版 | 单个新建、批量导入、编辑后提交、批量修改后提交、单个复制重跑、批量复制重跑 |
| 运营版 | 单个新建、批量导入、编辑后提交、批量修改后提交、单个复制重跑、批量复制重跑 |

美工版、运营版任务抽屉、批量导入和批量修改中的“模型与数量配置”，标普A+行问号提示统一显示：

> 对应亚马逊后台普通A+模块中最小尺寸为970*600的图，目前仅阿里绘蛙和LinkFox支持，LinkFox会等比放大到2k多使得展示效果更清晰更优。

本期仅更新上述提示文案，问号图标、提示触发方式和现有布局保持不变。

需要回归但无需分别开发的现有链路包括：

- 美工版、运营版任务列表、任务查看、审核工作台、沉浸式大屏和已完成记录中的标普A+类型及模型来源展示；
- 美工版标普A+审核通过后推送产品库“A+图片”的链路；
- 运营版标普A+审核通过后的现有 A+ 管理链路；
- 任务配置、生成过程、图片结果及现有数据同步中对阿里绘蛙标普A+的记录和识别。

### 2. 阿里绘蛙建任务传参

阿里绘蛙商品套图建任务接口：

https://huiwa.yuque.com/org-wiki-huiwa-kpqu3p/gp328g/ghdn76cxe0iiu80p

本期传参规则如下：

| 业务数据 | 阿里绘蛙字段 | 类型 | 处理规则 |
|---|---|---|---|
| 阿里绘蛙标准普通A+图计划张数 | `aplusNum` | Integer | 取当前任务阿里绘蛙模型下的标普A+计划张数；第三方接口允许 `0～12` 张。 |
| 任务已保存的生成图片语言 | `outputLanguage` | String | 复用现有阿里绘蛙卖点图的语言编码映射；历史任务无语言值时按英语 `en` 处理。 |

具体规则：

1. 当前用户对应的阿里绘蛙 `aplus` 未配置或配置为 `0` 时，标普A+继续保持不可用，本次任务不生成该类型图片；其他已开放图片类型按现有规则处理。
2. `aplus` 配置为 `1～12` 时，用户可在现有模型与数量配置中填写不超过配置上限的计划张数；提交后将任务实际计划张数传入 `aplusNum`。
3. 阿里绘蛙接口对 `aplusNum` 的硬限制为 `0～12`。管理员配置页面继续沿用现有非负整数校验，不新增12张前端或后端硬上限；管理员配置和后续业务初始化表格必须保证阿里绘蛙 `aplus` 值不超过12。
4. `outputLanguage` 读取任务已保存语言，不固定传 `en`，也不新增第二套语言选项或映射。编辑、单个复制重跑、批量复制重跑继续沿用任务已有语言；历史任务无语言值时按英语处理。
5. 本期不读取、不传递 `aplusScenes`。该字段对应A+参考图片URL列表，属于二期规划。
6. 现有“A+图排版版式”及 LinkFox `aPlusStyles` 继续为 LinkFox 专属能力，不映射为阿里绘蛙 `aplusScenes`，也不传给阿里绘蛙。
7. 阿里绘蛙建任务失败时沿用现有失败处理，不新增自动重试、接口降级、状态门槛或失败后改用其他模型的规则。

### 3. 查询结果类型映射

阿里绘蛙查询图片生成结果接口：

https://huiwa.yuque.com/org-wiki-huiwa-kpqu3p/gp328g/lcf8hemny07b8avi

处理规则：

1. 沿用现有 `taskId` 查询、轮询、主任务和子任务状态判断、图片结果关联及落库逻辑。
2. 将 `imageResults[].imageType=7` 识别为普通A+图，并映射为系统现有标准普通A+图类型。
3. 每个 `imageResults[]` 对象中的 `taskId`、`imageUrl`、`imageType`、`width`、`height` 作为同一张图片的结果数据处理，不通过外层 `imageUrls[]` 下标猜测图片类型或强行关联。
4. `imageResults[].width`、`height` 继续沿用 M-36575 已确认的阿里绘蛙图片宽高存储和异常兼容规则，本期不重复改造。
5. 阿里绘蛙文档的通用成功示例中存在 `imageType=null`，但字段说明约定普通A+图返回 `7`。提测和上线前必须使用真实标普A+任务验证实际返回；如真实结果未返回 `7`，需先与阿里绘蛙确认并反馈产品，不得依赖数组顺序自行建立兜底映射。

### 4. 配置开放与上线协作

1. 本期代码能力同时覆盖美工版和运营版，不因两端开放时间不同拆成两套实现。
2. 美工版后续由业务负责人提供初始化配置表格，明确 `aplus` 值和具体用户范围；收到表格后再安排批量 SQL 更新配置。未取得表格前，不自行补全配置值、用户范围或 SQL 数据。
3. 美工版业务初始化表格中的阿里绘蛙 `aplus` 值必须为 `0～12`。
4. 运营版本期不急于开放，生产配置继续保持未配置或 `aplus=0`；后续业务确认开放范围后仅调整配置，不再为标普A+重复开发接口映射。
5. 本需求不新增管理员配置页面字段、校验或批量更新交互，也不把尚未提供的生产初始化数据作为本期 PRD 的固定配置明细。
6. 提测时可使用符合 `0～12` 约束的测试配置分别验证美工版、运营版链路；生产是否对具体用户开放以业务后续配置表格和实际配置为准。

### 5. 现有业务兼容

1. 美工版、运营版现有标普A+页面入口、矩阵行、类型筛选、生成图片语言字段及其默认值、保存和回显规则保持不变。
2. 美工版标普A+继续使用美工版现有审核规则，不套用运营版最多审核通过7张的限制；审核通过后继续使用产品库A+图片专门接收链路并展示在“A+图片”，不进入 A+ 管理。
3. 运营版标普A+继续沿用现有最多审核通过7张及 A+ 管理推送规则，本期不调整审核上限、审核相关提示文案或推送去向。
4. 历史任务、历史图片和历史审核结果不补数据、不回刷、不自动新增阿里绘蛙标普A+计划数。
5. 沿用现有个人配置缓存规则。历史缓存中的阿里绘蛙标普A+数量为 `0` 时，后续管理员将配置上限调高也不自动改写用户缓存；用户可在现有配置界面按需调整，并在后续成功操作后更新缓存。
6. 单个复制重跑、批量复制重跑继续完整继承原任务启用模型、模型与图片类型数量矩阵和生成图片语言；原任务未配置阿里绘蛙标普A+时不自动增加。
7. LinkFox、自研模型及阿里绘蛙其他图片类型的建任务、查结果、审核和推送逻辑保持不变。

## 风险描述

| 风险 | 处理方式 |
|---|---|
| 阿里绘蛙真实标普A+结果未按文档返回 `imageType=7` | 提测和上线前使用真实任务核对；不按数组下标猜测类型，发现不一致时先由阿里绘蛙确认并反馈产品。 |

## 验收标准

| # | 验收场景 | 预期结果 |
|---:|---|---|
| 1 | 美工版、运营版分别配置阿里绘蛙 `aplus=1～12`，通过单个新建和批量导入创建任务 | 标普A+实际计划张数正确传入 `aplusNum`，同一请求中的其他图片类型数量不受影响。 |
| 2 | 分别通过编辑后提交、批量修改后提交、单个复制重跑、批量复制重跑创建新阿里绘蛙任务 | 所有入口复用同一建任务映射，`aplusNum` 与新任务实际计划张数一致。 |
| 3 | 美工版、运营版分别进入任务抽屉、批量导入和批量修改，触发“模型与数量配置”中标普A+行的问号提示 | 三个入口均显示完整文案“对应亚马逊后台普通A+模块中最小尺寸为970*600的图，目前仅阿里绘蛙和LinkFox支持，LinkFox会等比放大到2k多使得展示效果更清晰更优。”；问号图标、提示触发方式和现有布局不变。 |
| 4 | 分别创建仅含阿里绘蛙标普A+、同时包含标普A+和其他图片类型的任务 | 两种组合均可正常建任务，`aplusNum` 只表示普通A+图数量，其他类型继续使用各自现有字段。 |
| 5 | 选择英语和至少一种非英语创建阿里绘蛙标普A+任务 | `outputLanguage` 复用现有阿里绘蛙卖点图映射，分别传入任务所选语言对应编码，不固定为 `en`。 |
| 6 | 历史任务没有语言值，或基于该任务执行单个复制重跑、批量复制重跑 | 页面和新任务按英语兼容，阿里绘蛙请求传 `outputLanguage=en`。 |
| 7 | 检查阿里绘蛙标普A+建任务请求 | 正确传入 `aplusNum` 和 `outputLanguage`；不传 `aplusScenes`、LinkFox `aPlusStyles` 或其他未确认的A+参考图参数。 |
| 8 | 阿里绘蛙 `aplus` 未配置或配置为 `0` | 标普A+保持不可用，本次任务不生成该类型图片；其他已开放图片类型按现有规则处理。 |
| 9 | 使用 `aplus=12` 的测试配置创建任务，并回归管理员配置页面 | 任务可按12张上限正常提交；管理员配置页面继续执行现有非负整数校验，不因本需求新增12张通用校验或页面交互。 |
| 10 | 使用真实阿里绘蛙标普A+任务查询结果 | 每张普通A+图片在自身 `imageResults[]` 对象中返回 `imageType=7`，系统正确识别为标普A+并保存对应图片、宽高和模型来源。 |
| 11 | 真实标普A+结果的 `imageType` 未返回或为 `null` | 该场景不满足本需求验收；不使用 `imageUrls[]` 下标猜测类型，先与阿里绘蛙确认实际返回口径并反馈产品，确认后再决定处理方案。 |
| 12 | 阿里绘蛙任务处于生成中、生成成功、生成失败或安全审核不通过 | 沿用现有状态、轮询、失败原因和任务流转规则，不新增重试、降级或状态判断。 |
| 13 | 美工版完成阿里绘蛙标普A+生成、审核和推送回归 | 图片按现有美工规则审核，不套用运营版7张上限；审核通过后进入产品库“A+图片”，不进入 A+ 管理。 |
| 14 | 运营版使用测试配置完成阿里绘蛙标普A+生成、审核和推送回归 | 继续执行运营版现有7张审核上限和 A+ 管理推送规则；生产未开放用户仍保持不可用。 |
| 15 | 查看历史任务、历史缓存及原任务配置，并执行复制重跑 | 历史数据不回刷；缓存中的 `0` 不因管理员提高上限自动变为正数；新任务继承原任务矩阵和语言，不自动增加标普A+。 |
| 16 | 回归 LinkFox、自研和阿里绘蛙其他图片类型 | 原有建任务、结果识别、语言、审核、展示和推送逻辑不受影响。 |
| 17 | 美工初始化表格尚未提供、运营生产配置保持关闭时发布代码 | 两端共享接口能力已具备；系统不自行创建生产配置，后续可按业务确认通过配置开放，无需再次修改标普A+接口映射。 |
