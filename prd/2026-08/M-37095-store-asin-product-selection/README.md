## 业务背景和价值

运营版 AI 生图在新增任务查询及批量导入店铺 ASIN 时，会使用店铺 ID（`sourceId`）+ ASIN 调用 Amazon Listing 接口查询商品资料，并使用选中资料的 MSKU 和 SKU 继续现有商品处理链路。

同一店铺 ID + ASIN 可能返回多套商品资料。现有多套资料处理依赖“FBA 新品中的第一套”，没有先统一排除已删除、禁显资料，也没有在同级资料中按更新时间择优。已确认案例中，现有逻辑取到了一套已删除资料，不能满足业务实际使用诉求。

实际接口抽查还发现，同一查询组合返回的多套资料中，`sku` 不保证全部相同，部分资料的 `sku` 可能为空。由于运营 AI 生图实际链路同时依赖 `msku` 和 `sku`，两个字段必须取自最终命中的同一套资料，且任一字段为空时该资料均不可作为最终结果。

本需求将商品资料的有效性、在线状态、完整性、新品属性、配送与备货情况拆分为独立判断维度，建立统一、可降级的择优规则：优先选取更适合当前业务使用的资料；没有完全满足最优条件的资料时，仍从非删除、非禁显资料中按优先级降级取数，降低无结果和重复提出零散取数优化的概率。

## 需求概述

本需求仅调整 AI 生图调用现有 Amazon Listing 接口后，对同一店铺 ID + ASIN 返回的多套商品资料进行筛选、排序，确定唯一最终命中对象，并成对选取 MSKU 和 SKU 的逻辑。最终命中后，标题和类目也必须从该对象读取，但不参与筛选、排序或结果有效性判断。

- 直接改造点：AI 生图运营端共用的店铺 ID + ASIN 商品资料择优逻辑。
- 回归入口：运营版新增任务抽屉、运营版批量导入店铺 ASIN 弹窗。
- 不调整上游接口的请求参数、响应字段和接口内部逻辑。
- 不调整页面交互、展示样式、提示文案及批量导入格式，无需单独制作 HTML 原型。
- 确定最终命中对象后，MSKU、SKU、标题和类目均从该对象读取；后续商品信息查询、字段回显、快照、任务创建、审核和推送等现有流程保持不变。

## 功能需求

### 1. 查询范围和数据口径

各入口继续使用店铺 ID（`sourceId`）+ ASIN 调用现有接口，查询值和匹配方式不变。接口返回同一查询组合下的多套商品资料时，每套资料为一个独立候选项。

本需求使用的字段如下：

| 字段路径 | 含义 | 本期用途 |
|---|---|---|
| `isDeleted` | 是否删除，`0` 为未删除，非 `0` 为已删除 | 明确删除资料的硬排除条件 |
| `visibleStatus` | 禁显状态，`0` 为可显示，`1` 为禁显 | 禁显资料的硬排除条件 |
| `delStatus` | 详情页面删除状态，`0` 为正常，`1` 为删除 | 详情已删除资料的硬排除条件 |
| `statusInfoDTO.status` | 在线状态，`1` 为在售，`3` 为非在售 | 第一级排序条件 |
| `statusInfoDTO.isIncomplete` | 是否为不完整数据，`0` 为否，`1` 为是 | 第二级排序条件 |
| `conditionType` | 商品成色类型 | 第三级排序条件 |
| `statusInfoDTO.deliveryType` | 配送类型，`0` 为 FBM，`1` 为 FBA | 与备货状态组合形成第四级排序条件 |
| `isStock` | 是否备过货，`0` 为未备货，`1` 为备过货 | 与配送类型组合形成第四级排序条件 |
| `updateTime` | 商品资料更新时间 | 第五级排序条件 |
| `msku` | 商品资料对应的 MSKU | 与 `sku` 成对作为最终结果；字段缺失或空值的候选不可作为结果 |
| `sku` | 商品资料对应的系统 SKU | 与 `msku` 成对作为最终结果；字段缺失或空值的候选不可作为结果，不参与排序 |
| `name` | Listing 标题 | 从最终命中对象读取；不参与排序或结果有效性判断 |
| `classifications.namePath` | 亚马逊分类树名称全路径 | 从最终命中对象读取；不参与排序或结果有效性判断 |

`statusInfoDTO.status`、`statusInfoDTO.isIncomplete`、`statusInfoDTO.deliveryType` 均位于 `statusInfoDTO` 对象下，`classifications.namePath` 位于 `classifications` 对象下；其他本期使用字段均位于单套商品资料对象顶层。研发不得因字段名称相近而从错误层级取值。

### 2. 硬排除规则

接口返回候选资料后，先排除符合以下任意一项的资料：

1. `isDeleted != 0`；
2. `visibleStatus == 1`；
3. `delStatus == 1`。

以上三类资料属于明确不可用资料，不参与后续排序，也不得在没有更优资料时重新进入降级范围。

未命中以上明确值的资料继续参与排序。以上三个字段缺失、`null` 或无法识别时，不按“已删除”或“禁显”直接排除，也不使用这些字段增加排序权重。

### 3. 多维度择优排序

完成硬排除后，对剩余候选资料按下列顺序逐级比较。只有前一维度相同时，才比较下一维度；各维度相互独立，不把 FBA 与新品绑定为一个条件，也不将 `isStock` 作为独立权重重复计算。

| 顺序 | 维度 | 从高到低的优先级 |
|---|---|---|
| 1 | 在线状态 | `statusInfoDTO.status = 1` 在售 > 缺失或其他未知值 > `statusInfoDTO.status = 3` 非在售 |
| 2 | 资料完整性 | `statusInfoDTO.isIncomplete = 0` 完整 > 缺失或其他未知值 > `statusInfoDTO.isIncomplete = 1` 不完整 |
| 3 | 商品成色 | 新品 > 非新品或未知类型 |
| 4 | 配送与备货 | FBA 且备过货 > FBA 未备货或备货状态未知 > FBM > 配送类型缺失或未知 |
| 5 | 更新时间 | `updateTime` 按时间倒序，较新的资料优先；空值或无法解析的值排在有效时间之后；多个候选均无有效时间时视为同级，不比较原始字符串 |
| 6 | 完全相同 | 保持接口原始返回顺序，较早返回的候选排在前面；最终是否选中仍需满足 MSKU/SKU 结果有效性门槛 |

新品仅包括以下 `conditionType`：

- `new_new`
- `new_open_box`
- `new_oem`

除以上三个值外，翻新、二手、收藏、俱乐部及缺失或未知的 `conditionType` 均归入“非新品或未知类型”，本期不再细分其内部优先级。

配送与备货的组合口径如下：

| 优先级 | 判断条件 | 说明 |
|---|---|---|
| 1 | `deliveryType = 1` 且 `isStock = 1` | FBA 且备过货 |
| 2 | `deliveryType = 1` 且（`isStock != 1` 或 `isStock` 缺失） | FBA 未备货或备货状态未知 |
| 3 | `deliveryType = 0` | FBM；不使用 `isStock` 将其提升到 FBA 之前 |
| 4 | `deliveryType` 缺失或为其他未知值 | 配送类型未知 |

库存数量、销量、价格、Buy Box、评价、排名、到货时间、头程信息、标签及接口返回的其他字段均不参与本期筛选和排序，不得额外增加未确认的权重。

### 4. 最终命中对象、MSKU/SKU 取值和降级兜底

1. 完成硬排除和排序后，从最高优先级候选资料开始读取同一结果对象内的 `msku` 和 `sku`，两个字段不得跨资料拼接，也不得选中某套资料的 `msku` 后再取接口第一条或其他资料的 `sku`。
2. 当前候选的 `msku` 或 `sku` 任一字段缺失、为 `null`、空字符串或仅包含空白字符时，该候选不满足结果有效性门槛，跳过并继续读取下一套资料。
3. 只要仍存在未被硬排除且 MSKU、SKU 均有效的候选资料，就按排序结果降级取第一套可用资料，不因其为非在售、不完整、非新品、FBM 或排序字段未知而直接返回无结果。
4. 接口无数据、所有资料均被硬排除，或所有剩余资料均无法同时提供有效 MSKU 和 SKU 时，沿用现有查询失败处理和提示，不新增重试、其他数据源或新的提示文案。
5. 确定最终命中对象后，`msku`、`sku`、`name` 和 `classifications.namePath` 均从该对象读取，不得从接口第一条或其他候选对象拼接标题或类目；后续五点描述使用当前查询的 `sourceId` 和最终命中对象的 `msku` 查询关联。
6. `name` 和 `classifications.namePath` 不参与筛选、排序或结果有效性判断。最终命中对象的标题或类目缺失、为 `null`、空字符串或纯空白时，保持为空并沿用现有人工完善规则，不得为了补齐这些字段改选下一套资料，也不得使用产品库同类字段兜底。

### 5. 单个查询与批量导入一致性

- 运营版新增任务查询和批量导入使用同一套规则。
- 批量导入继续使用现有输入格式，每行一个店铺 + ASIN，单次最多 50 行。
- 批量场景中，每个店铺 ID + ASIN 组合均独立执行硬排除、排序和 MSKU/SKU 成对取值；不得用某一行的候选资料或排序结果影响其他行。
- 无论实现上采用逐条请求还是批量请求，同一店铺 ID + ASIN 的最终结果必须与单个查询一致。
- 本期不改变批量导入的行间成功、失败处理方式；单行无有效商品资料时，其他行继续按现有批量流程处理。

### 7. 兼容范围和不影响范围

- 上游接口地址、`sourceId` + ASIN 请求方式、响应结构和接口提供方逻辑均不调整。
- 本需求只消费现有响应字段，不要求接口新增、删除、重命名或修改字段类型。
- 接口真实响应与接口文档不一致时，以真实响应为准；接口文档用于确认字段业务含义，不作为臆造缺失字段的依据。
- 确定最终命中对象并从同一对象取得 MSKU、SKU、标题和类目后，沿用现有商品信息获取、字段回显、数据快照、任务创建、审核及推送链路。
- 不重算已创建的历史任务，不修复历史快照，不对历史已选 MSKU 或 SKU 做专项回刷。
- 不影响美工版及其他不使用本取数逻辑的业务端。

## 风险描述

| 风险 | 控制要求 |
|---|---|
| `statusInfoDTO` 下三个参与排序的字段层级读取错误会导致排序失效 | 按本 PRD 列明的完整字段路径解析，并使用真实接口响应完成联调 |
| 若把 FBA 与新品绑定，或重复使用 `isStock` 加权，会改变已确认的独立维度优先级 | 必须严格按逐级排序表实现，不得增加复合权重或未确认字段 |
| 同一查询组合下的 `sku` 不保证相同，若将选中资料的 `msku` 与其他资料的 `sku` 拼接，会造成商品关联错误 | MSKU 和 SKU 必须从最终命中的同一个结果对象成对读取；任一字段缺失或为空时继续降级 |
| 只切换最终命中的 MSKU 和 SKU，却仍从接口第一条或其他候选读取标题、类目，会造成同一任务字段跨资料拼接 | MSKU、SKU、标题和类目必须从最终命中的同一个结果对象读取；标题或类目为空时保持为空，不改选其他资料 |
| 接口原始顺序不稳定，继续依赖“第一条”可能重复出现错误选择 | 仅在全部已确认维度完全相同时，才使用接口原始顺序兜底 |
| 两个运营入口若未复用同一逻辑，可能出现相同店铺 ID + ASIN 结果不一致 | 两个入口分别回归，并验证单个查询与批量导入结果一致 |

## 验收标准

| 编号 | 验收场景 | 预期结果 |
|---|---|---|
| 1 | 分别在运营版新增任务和批量导入中查询同一店铺 ID + ASIN | 两个入口使用同一规则；候选资料相同时选中同一套资料的相同 MSKU 和 SKU |
| 2 | 候选资料中分别存在 `isDeleted != 0`、`visibleStatus = 1` 或 `delStatus = 1` | 命中任一条件的资料均被排除，且不得重新进入降级范围 |
| 3 | 查询 `sourceId = 26342`、`ASIN = B0811WKXQ8` | 排除已删除的 `TK1026076FE264RV`，最终从同一套资料取得 `msku = 5H144012G55GAVMF`、`sku = 6409613` |
| 4 | 同一查询组合的多套资料存在不同 `sku`、`name` 或 `classifications.namePath`，且最终命中资料不是接口第一条 | `msku`、`sku`、`name` 和 `classifications.namePath` 均取自最终命中的同一个结果对象，不得使用接口第一条或其他资料的字段 |
| 5 | 多套资料的在线状态不同，其他更高维度无冲突 | 在售优先于未知状态，未知状态优先于非在售；不因较低维度更优而越级 |
| 6 | 分别构造三组单变量场景：在线状态相同且仅完整性不同；前两维相同且仅新品属性不同；前三维相同且仅配送与备货组合不同 | 三组分别按完整 > 未知 > 不完整、新品 > 非新品或未知、FBA 已备货 > FBA 未备货或未知 > FBM > 配送未知进行选择，不受更低维度影响 |
| 7 | 两套资料在前四个维度完全一致，但 `updateTime` 不同 | 选中有效更新时间较新的资料；有效时间优先于空值或无法解析的时间 |
