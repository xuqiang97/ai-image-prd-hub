## 业务背景和价值

M-36678 已在美工版 AI 生图系统上线人物检测和必要标记能力。只有任务内全部生成成功图片均取得“有人物”或“无人物”的有效检测结果，且有人物图片均完成图片元数据标记等合规处理后，任务才允许从“生图中”进入“待审核”并继续推送。

美工版 AI 生图系统推送的图片全部是 AI 生图；产品库的图片则来自 AI 生图、PS 制作等多个来源。产品库现已在图片维度增加“AI非人”和“AI人物”属性，并在商品图、A+ 图接收接口中增加对应字段。当前美工版 AI 生图尚未传递这两个字段，产品库无法随图片接收结果区分“AI 生图无人物”和“AI 生图有人物”。

本需求在现有商品图、A+ 图推送请求中补充图片级人物检测结果，使产品库收到图片时同步保存正确属性，不改变现有审核和推送流程。

## 需求概述

M-36754 上线后，美工版 AI 生图发生的所有正常商品图、A+ 图推送，均根据每张图片现有的人物检测结果，向产品库二选一传递：

- 无人物：`AINoHuman=1`；
- 有人物：`AICharacter=1`。

生效范围按推送发生时间判断，不按图片生成时间判断。较早生成的图片在 M-36754 上线后进入现有正常推送流程时，同样执行新传参规则。

本需求不对产品库已接收的历史图片发起专项重推、替换或补充属性。美工版存量图片是否需要重推产品库，后续根据业务需要单独组织会议并形成独立方案。

## 功能需求

### 1. 影响接口和现有推送粒度

本需求修改美工版 AI 生图调用的两个现有产品库接口：

1. 推送商品图片到产品库接口：http://showdoc.zhcxkj.com/web/#/18/7086
2. 推送 A+ 图到产品库接口：http://showdoc.zhcxkj.com/web/#/18/6918

两个产品库接口均以 SKU 为接收维度，对应美工版 AI 生图的 SKU 任务维度。现有规则为：将一个 SKU 任务下审核通过的多张图片组成一次接口请求，按图片类型调用对应的商品图或 A+ 图接口。

本需求只在每张图片的现有请求对象中增加人物检测结果字段，不改变以下现有逻辑：

- SKU 任务与产品库 SKU 的关联关系；
- 审核通过图片的选取范围；
- 商品图、A+ 图对应的接口及调用时机；
- 单次请求包含的图片范围和现有调用次数；
- 现有请求字段、图片 URL、接口响应处理、失败状态及重试机制。

### 2. 图片级新增入参

产品库两个接口均已增加以下非必传字段，字段位于每张图片对象内，与该图片的 URL 字段平级：

| 字段 | 类型 | 产品库属性 |
|---|---|---|
| `AINoHuman` | `Integer` | AI非人 |
| `AICharacter` | `Integer` | AI人物 |

两个字段在产品库接口中均定义为非必传；但对美工版 AI 生图在本需求范围内的正常推送，每张图片必须根据自身检测结果二选一传递。

传参读取图片表现有 `personDetectStatus`，沿用 M-36678 已上线、M-36753 已明确的枚举口径：

| `personDetectStatus` | 检测结果 | `AINoHuman` | `AICharacter` | 产品库保存属性 |
|---:|---|---:|---:|---|
| `1` | 有人物 | 请求对象中不包含该字段 | 传 JSON 数字 `1` | AI人物 |
| `2` | 无人物 | 传 JSON 数字 `1` | 请求对象中不包含该字段 | AI非人 |

传参要求：

1. “不传”表示当前图片的请求对象中不包含该字段，不得改为传 `0`、`null`、空字符串或其他默认值。
2. 同一张图片不得同时传递 `AINoHuman` 和 `AICharacter`，也不得在正常推送时两个字段均不传。
3. 同一 SKU 请求包含多张图片时，每张图片分别读取自身检测结果并独立映射；不得使用任务级统一值覆盖全部图片。
4. 同一请求允许同时包含“AI非人”和“AI人物”图片，各图片字段必须与自己的 URL 保持对应，不得串图。
5. 商品图和 A+ 图两个接口使用完全相同的字段名称、大小写、类型和映射规则。

### 3. 与现有人物检测门禁的衔接

本需求复用 M-36678 已上线的人物检测、必要标记和任务门禁，不新增检测调用、图片元数据处理或推送阶段的二次门禁：

1. 检测结果为“未检测”或“检测失败”时，任务继续停留在“生图中”，不能进入审核和后续推送。
2. 无人物图片需完成结果保存；有人物图片需完成检测、图片元数据标记、新图片地址更新及 M-36678 规定的合规处理。只有处理完成后，任务才可以进入审核和推送。
3. 因此，正常推送只映射 `personDetectStatus=1` 或 `2`；不得将未检测、检测失败、空值或非法值映射为任一产品库属性。

本需求只读取 `personDetectStatus` 完成传参，不重新检测，也不根据图片 URL、XMP 标记或其他字段反向推断结果。

### 4. 生效范围和历史边界

1. M-36754 上线后发生的所有正常商品图、A+ 图推送均执行新传参规则。
2. 生效范围以推送发生时间为准；图片在 M-36754 上线前生成、但在上线后进入现有正常推送流程时，也必须传递对应字段。
3. AI 生图系统自身存量图片已完成检测和必要标记，但本需求不新增 SQL、批处理、专项任务或人工入口，不对产品库已接收的历史图片进行批量重推、替换或属性补录。
4. 后续如业务确认需要治理产品库历史图片，应另行明确数据范围、重推条件、下游影响和验收标准。

### 5. 产品库现有属性和上线协作

1. 产品库原有“AI”属性及其现有逻辑保持不变；本需求仅新增 `AINoHuman`、`AICharacter` 两个字段的传参，不新增与原“AI”属性的联动规则。
2. 产品库两个接口的 `AINoHuman`、`AICharacter` 字段及页面“AI非人”“AI人物”属性均已上线，本需求无需等待产品库再次开发。
3. 美工版 AI 生图完成开发后，需分别使用商品图和 A+ 图接口完成联调，核对请求参数、SKU、图片 URL、单图检测结果及产品库最终属性。
4. 产品库中 PS 制作等其他来源图片不属于本需求的改造和验收范围。

## 风险描述

| 风险 | 处理方式 |
|---|---|
| SKU 请求包含多张且检测结果不同时，按任务统一传值导致图片属性错误 | 必须在单图对象内逐张读取和映射，分别核对字段与图片 URL。 |
| `personDetectStatus` 与产品库字段映射反向，或同图传入两个字段 | 固定使用 `1 → AICharacter=1`、`2 → AINoHuman=1` 的互斥映射并逐项验收。 |
| 将产品库非必传字段误解为 AI 生图侧正常推送时可以不传 | 美工版 AI 生图正常推送时，每张图片必须根据检测结果二选一传递。 |
| 新字段与产品库原有“AI”属性产生错误联动 | 本需求只传 `AINoHuman`、`AICharacter`，原“AI”属性逻辑保持不变。 |
| 将本次增量传参误解为产品库历史图片已完成治理 | 明确不进行产品库历史图片专项重推或属性补录，后续是否治理由业务另行确认。 |

## 验收标准

| # | 验收场景 | 预期结果 |
|---:|---|---|
| 1 | 一个商品图 SKU 任务中，多张审核通过图片分别检测为有人物、无人物 | 仍按现有规则调用一次商品图接口；每张图片与自身 URL 对应，按 `personDetectStatus` 独立映射，不串图、不按任务统一赋值。 |
| 2 | 一个 A+ 图 SKU 任务中，多张审核通过图片分别检测为有人物、无人物 | 仍按现有规则调用一次 A+ 图接口；字段名称、类型、映射方式及单图对应关系与商品图接口一致。 |
| 3 | `personDetectStatus=2` 的图片正常推送 | 当前图片对象包含 JSON 数字 `AINoHuman: 1`，不包含 `AICharacter`；产品库对应图片显示“AI非人”，不显示“AI人物”。 |
| 4 | `personDetectStatus=1` 且已完成必要标记的图片正常推送 | 当前图片对象包含 JSON 数字 `AICharacter: 1`，不包含 `AINoHuman`；产品库对应图片显示“AI人物”，不显示“AI非人”。 |
| 5 | 检查“不传”字段及字段类型 | 未传字段在当前图片请求对象中不存在，不传 `0`、`null`、空字符串或字符串 `"1"`；实际传递值为 JSON 数字 `1`。 |
| 6 | M-36754 上线前生成的图片，在上线后进入现有正常推送流程 | 按推送发生时间执行新规则，每张图片均根据自身检测结果二选一传递新字段。 |
| 7 | 任务存在未检测或检测失败图片 | 继续按 M-36678 停留在“生图中”，不能进入审核和推送；本需求不新增降级推送或默认属性。 |
| 8 | 连续推送不同 SKU 任务 | 每次请求只包含当前 SKU 任务审核通过的对应类型图片，图片检测结果和产品库属性不跨 SKU、任务或请求串写。 |
| 9 | 检查产品库原有“AI”属性 | 新字段上线前后，原“AI”属性继续按现有逻辑处理，不因 `AINoHuman`、`AICharacter` 新增未确认的自动联动。 |
| 10 | 产品库接口返回失败或现有异常响应 | 美工版 AI 生图沿用现有失败状态、日志和重试机制，不因新增字段改变请求粒度或异常处理方式。 |
| 11 | 检查产品库已接收的历史图片 | 本需求不会自动批量重推、替换或补录“AI非人”“AI人物”属性；后续是否治理等待独立业务确认。 |
| 12 | 商品图和 A+ 图分别完成联调 | 两个接口均正确接收新字段，SKU、图片 URL、`personDetectStatus`、传入字段及产品库最终属性逐图一致。 |
