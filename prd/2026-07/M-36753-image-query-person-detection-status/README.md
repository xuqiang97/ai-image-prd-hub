## 业务背景和价值

M-36678 已在美工版和运营版 AI 生图系统上线人物检测和必要标记能力，图片表已保存 `personDetectStatus` 人物检测结果。运营版非 A+ 商品图由 Listing 实时调用图片查询接口获取，当前接口返回图片及最新 `imageUrl`，但单图结果尚未提供人物检测结果。

本需求先由 AI 生图侧补齐接口出参，使 Listing 后续可根据自身排期接入人物检测结果，无需重复判断图片是否包含人物。Listing 本期不需要同步开发、保存或展示该字段。

M-36508 是同一接口的后续查询维度扩展需求，将增加站点+ASIN及纯 ASIN查询模式。本需求作为独立接口扩展先行上线；M-36508 后续实施时必须保留本次新增字段。

## 需求概述

扩展现有接口：

`POST /open/aiImageOperation/image/query`

在成功响应的 `data.images[]` 单图对象中新增 `personDetectStatus`，直接返回图片表中已经落库的 AI 生成人物检测结果。

本期仅新增响应字段，不新增请求参数，不改变现有店铺+ASIN查询逻辑、可返回图片范围、排序、鉴权、异常处理及 `imageUrl` 返回口径。接口可独立开发、测试和上线；Listing 本期不接入新字段，后续由 Listing 自行安排。

## 功能需求

### 1. 新增单图出参

| 字段 | 所在层级 | 类型 | 数据来源 | 返回规则 |
|---|---|---|---|---|
| `personDetectStatus` | `data.images[]` | `Integer` | 图片表同名字段 | 查询有图片时，每个单图对象均返回；按对应图片记录的当前落库值逐条映射。 |

`personDetectStatus` 取值如下：

| 值 | 业务含义 |
|---:|---|
| `0` | 未检测 |
| `1` | 有人物 |
| `2` | 无人物 |
| `3` | 检测失败 |

处理规则：

1. 图片表 `personDetectStatus` 为 `0`、`1`、`2`、`3` 时，接口原值返回。
2. 历史记录中的 `null` 或空值统一返回 `0`，与 M-36678 的“未检测”兼容口径一致。
3. 接口不得使用单一 Boolean 替代四态枚举，不得把“无人物”“未检测”和“检测失败”合并。
4. 接口只读取已有检测结果，不重新调用人物检测接口，不修改图片表检测结果，也不根据 `imageUrl`、XMP 标记或标记处理状态推断人物检测结果。
5. 提测前需核查图片表不存在 `0`～`3` 之外的值；如存在，按数据异常反馈产品确认，不得自行增加枚举或改变映射规则。

### 2. 响应示例

以下仅展示与本需求相关的关键字段，其他现有字段保持不变：

```json
{
  "success": true,
  "data": {
    "images": [
      {
        "id": 187135,
        "imageUrl": "https://example.com/aio_l_88104002.jpg",
        "personDetectStatus": 1
      },
      {
        "id": 187136,
        "imageUrl": "https://example.com/aio_l_88104003.jpg",
        "personDetectStatus": 2
      }
    ]
  }
}
```

查询成功但没有符合条件的图片时，继续沿用现有空结果结构，本需求不额外增加顶层状态或默认图片对象。

### 3. 现有调用兼容

- 当前 Listing 已在线使用该接口的店铺+ASIN查询能力，本次仅在单图对象中增加字段，不删除、不重命名、不改变任何现有字段类型。
- 原请求参数、参数校验、查询范围、图片可用条件、图片类型范围、排序、全量返回规则和无数据处理保持不变。
- 接口鉴权及现有数据范围保持不变，不因新增字段扩大或缩小当前账号可查询的数据。
- Listing 本期无需读取、保存、展示或使用 `personDetectStatus`；未使用该字段时，原取图、展示和选择流程继续有效。
- 接口上线前必须使用当前线上 Listing 版本完成真实兼容验证，确认新增字段不会因严格反序列化、字段校验或前端解析导致现有取图异常。
- 接口提测或上线前，由产品徐强同步 Listing 负责人，说明 `personDetectStatus` 的字段位置、`Integer` 类型、四个枚举值，以及 Listing 本期无需同步开发、后续可自行安排接入。
- 接口开发完成后更新 ShowDoc，补充 `personDetectStatus` 的所在层级、类型、四个枚举值及响应示例。

### 4. 与关联需求的衔接

- M-36678 是本字段的数据来源需求。本需求沿用其四态人物检测结果，不增加检测、标记、重试或历史刷数能力，也不返回标记处理状态。
- M-36753 可在 M-36508 之前独立上线。
- M-36508 后续扩展店铺+ASIN、站点+ASIN和纯 ASIN三种查询模式时，`personDetectStatus` 应作为届时已有单图字段继续返回；不得删除、重命名或改变类型和枚举含义。
- 本期不修改 M-36508 已确认的查询参数、模式识别优先级或查询范围。

## 风险描述

| 风险 | 处理方式 |
|---|---|
| 新增响应字段影响当前 Listing 严格解析 | 使用当前线上 Listing 版本调用升级后的接口，验证响应解析、图片展示和选择正常后再上线。 |
| 将人物检测结果误实现为 Boolean，导致状态含义丢失 | 固定使用 `Integer` 四态枚举，逐项验收 `0`～`3` 及历史空值映射。 |
| 将“有人物”等同于“已完成 XMP 标记” | 本字段只表达人物检测结果，不返回或推断标记处理状态。 |
| M-36508 后续改造响应结构时遗漏本字段 | 在关联需求和接口文档中明确该字段为届时已有字段，M-36508 三种查询模式均需保留。 |

## 验收标准

| # | 验收场景 | 预期结果 |
|---:|---|---|
| 1 | 分别查询 `personDetectStatus=0、1、2、3` 的图片 | 单图对象分别返回 `0、1、2、3`，业务含义依次为未检测、有人物、无人物、检测失败。 |
| 2 | 查询 `personDetectStatus` 为 `null` 或历史空值的图片 | 单图对象返回 `personDetectStatus=0`，不返回 `null`，也不省略该字段。 |
| 3 | 一次查询返回多张且检测结果不同的图片 | 每张图片按自身记录准确返回 `personDetectStatus`，不串图、不共用其他图片状态。 |
| 4 | 当前 Listing 继续按原参数调用店铺+ASIN查询 | 原查询范围、图片结果、排序、字段类型和 `imageUrl` 保持不变；每张图片仅新增 `personDetectStatus`。 |
| 5 | 使用当前线上 Listing 版本调用升级后的接口 | 请求和响应解析成功，原图片展示、选择和使用正常；Listing 不接入新字段也不受影响。 |
| 6 | 执行图片查询并检查人物检测链路和图片表 | 查询过程不调用人物检测接口，不修改 `personDetectStatus`、标记处理状态或 `imageUrl`。 |
| 7 | 查询无符合条件的图片 | 继续返回现有空结果，不因新增字段改变为接口异常，也不生成默认图片对象。 |
| 8 | 使用有效和无效鉴权分别调用接口 | 鉴权和现有数据范围与改造前一致，新增字段不扩大或缩小可查询范围。 |
| 9 | 检查图片表实际数据及接口响应 | 图片表不存在 `0`～`3` 之外的未确认值；接口不返回未定义枚举。 |
| 10 | 接口开发完成并准备交付 | 已向 Listing 负责人同步字段位置、`Integer` 类型、四个枚举值和本期无需同步开发的安排；ShowDoc 已补充字段定义及响应示例。 |
