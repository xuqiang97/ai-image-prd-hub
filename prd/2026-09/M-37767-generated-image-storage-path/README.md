## 业务背景和价值

美工版、运营版的生成图文件名已完成统一调整，前置需求为 M-36780：

https://pm.zhcxkj.com/zentao/story-view-36780.html

中间路径仍沿用现有公共方法的组织方式，包含组织归属目录、两端独立系统目录及重复的年月信息。本期以稳定的生图系统名称统一归档入口，保留环境隔离、业务端区分、日期归档和模型分类，便于长期管理与排查。

### 1. 当前路径与处理逻辑

当前使用公司阿里云华南1（深圳）的 OSS 存储桶 `irobotbox-hn1`，本次继续沿用。

OSS 访问域名：

https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/

两端完整 URL 结构如下：

```text
美工版：
{OSS域名}/1/Znyf/{环境目录}/AiImageGen/{模型目录}/{YYYYMM}/{YYYYMMDD}/{uniqueId}

运营版：
{OSS域名}/1/Znyf/{环境目录}/AiImageOperation/{模型目录}/{YYYYMM}/{YYYYMMDD}/{uniqueId}
```

| 路径部分 | 当前含义与规则 |
|---|---|
| `1` | 现有固定一级目录。 |
| `Znyf` | 原智能研发组织标识。 |
| 环境目录 | 随运行环境变化，生产环境为 `ProductionReleases`，现有测试环境目录为 `Staging`。 |
| `AiImageGen` / `AiImageOperation` | 分别对应美工版、运营版。 |
| 模型目录 | LinkFox 为 `Linkfox`，阿里绘蛙为 `Ali`，自研为 `Self`。 |
| `YYYYMM/YYYYMMDD` | 先按年月，再按完整日期归档，例如 `202609/20260924`。 |
| `uniqueId` | 数据库中的现有字段，同时作为包含扩展名的完整文件名。 |

现有 `uniqueId` 格式：

```text
未打标：
{系统SKU或ASIN}-{任务ID}-{模型编码}-{子模型编码}-{图片类型编码}-{序号}-{第三方图片ID}.{扩展名}

已打标：
tagged-{系统SKU或ASIN}-{任务ID}-{模型编码}-{子模型编码}-{图片类型编码}-{序号}-{第三方图片ID}.{扩展名}
```

美工版使用系统 SKU，运营版使用 ASIN。人物打标后的图片沿用原图所在目录，仅在文件名前增加 `tagged-`，不重新计算中间路径。

## 需求概述

本期统一美工版、运营版新生成图片的 OSS 中间路径，覆盖 LinkFox、阿里绘蛙、自研模型及其生成图打标链路。直接改造点为生成结果上传 OSS 时的路径构建逻辑及公共上传方法接入；不要求各页面分别实现路径拼接。

沿用现有 `uniqueId`、扩展名、人物检测与打标流程，以及图片记录关联和更新时机。不涉及页面展示调整、上传参考图命名或历史文件迁移。

## 功能需求

### 1. 新路径及调整原因

```text
https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/1/AiImage/{环境编码}/{业务端}/generated/{YYYY}/{MM}/{DD}/{模型目录}/{uniqueId}
```

| 调整项 | 具体规则 | 调整原因 |
|---|---|---|
| 域名与一级目录 | 保留现有 OSS 域名及 `/1/`。 | 沿用现有存储位置。 |
| 系统目录 | 删除 `Znyf`，统一使用 `AiImage`。 | 系统目录不再绑定组织归属。 |
| 环境 | 位于 `AiImage` 后，使用下表中的小写环境编码。 | 集中系统文件，并隔离各运行环境。 |
| 业务端 | 美工版为 `aig`，运营版为 `aio`，替代 `AiImageGen/AiImageOperation`。 | 两端采用相同层级，保留业务区分。 |
| 图片用途 | 固定为 `generated`。 | 明确目录存放生成结果图。 |
| 日期 | 采用 `YYYY/MM/DD`，取原图首次实际上传 OSS 的北京时间；年份四位，月、日固定两位。 | 按年、月、日分组，去除重复日期信息。 |
| 模型目录 | 保留 `Linkfox`、`Ali`、`Self`，移至日期后，大小写固定。 | 同一天图片先集中，再按模型分类。 |
| 文件名 | 直接拼接现有 `uniqueId`，不再次追加扩展名。 | 沿用已实施的图片命名规则。 |

### 2. 环境映射

| 环境编码 | 对应环境 |
|---|---|
| `prod` | 生产环境 |
| `staging` | 预发布环境，上线前验收使用 |
| `test` | 测试环境，日常联调和测试使用 |
| `dev` | 开发环境 |

环境编码由服务端部署配置确定，不由用户选择；枚举不代表新增四套环境。生产环境旧目录 `ProductionReleases` 映射为 `prod`；旧 `Staging` 按实际部署用途映射，日常测试使用 `test`，预发布验收使用 `staging`。发布前核对实际部署环境与编码的对应关系。

阿里绘蛙和自研模型分别使用 `Ali`、`Self` 目录，文件名使用对应图片现有的 `uniqueId`。

### 4. 生效范围与打标继承

- 上线后新创建的生成图片记录使用新路径，包括历史任务在上线后重新生成的新图片；允许同一任务同时存在新旧 URL。
- 已有图片记录、`uniqueId`、OSS 文件和 URL 不迁移，不执行专项回填、复制、重命名或删除；已有图片的技术重试沿用原地址。
- 打标图始终继承原图目录。原图在旧路径，后续打标仍在旧路径；原图在新路径，打标后仍在新路径。跨日打标不重新计算日期目录。
- 查询、预览、下载及下游读取使用图片记录中保存的完整 URL，不按新规则推算历史地址。

### 5. 公共方法与现有业务兼容

新路径规则只对本期两端生成图链路生效。公共上传方法通过兼容方式接入，其他项目、上传参考图和其他调用方的默认路径及行为不受影响。

发布前核对公共上传方法及现有访问权限、文件管理逻辑对旧路径前缀和层级的依赖，确保新目录可上传和访问。上传失败、重试、人物检测、打标以及图片记录更新均沿用现有处理机制，不因路径调整新增状态门槛或重试流程。

原有账号归属和访问权限不变，不因目录统一扩大图片可见范围。

## 验收标准

美工版、运营版须分别执行以下适用场景；模型覆盖 LinkFox、阿里绘蛙和自研，环境覆盖实际部署的环境。

| 场景 | 验收要求 |
|---|---|
| 新生成图上传 | 按新结构保存；两端分别进入 `aig/aio`，三模型分别进入 `Linkfox/Ali/Self`；URL 最后一段与现有 `uniqueId` 完全一致，含扩展名且不重复追加。 |
| 环境与日期 | 部署环境对应正确编码，不串环境；按原图首次实际上传的北京时间生成日期，验证跨日、跨月及月日补零，年月日来自同一时间。 |
| 人物打标 | 未打标图与打标图沿用现有文件名规则；打标图和原图同目录，跨日处理及历史旧路径原图打标均不改变目录。 |
| 增量与历史兼容 | 历史数据及文件原地址不变；历史任务新生成图片使用新路径；同一任务的新旧 URL 均可正常查询、预览和下载。 |
| 失败与重试 | 上传失败和重试执行现有机制；已有图片重试不切换地址，不因路径调整误关联图片记录。 |
| 公共调用与权限 | 上传参考图及其他公共方法调用方的路径和行为不变；原有账号权限分别验证有权、无权访问，新路径不扩大可见范围。 |
