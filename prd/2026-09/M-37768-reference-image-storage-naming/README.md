## 业务背景和价值

美工版、运营版上传参考图共用现有公共上传方法，路径和文件名仍采用 `AutoChoose/Production/AI/Generate`、`Generate_` 等命名。本期接续生成图的目录体系，统一参考图的系统归属、环境、业务端和日期层级，并通过 `reference-` 文件名前缀明确用途，便于归档和排查。

### 1. 当前路径与处理逻辑

当前使用公司阿里云华南1（深圳）的 OSS 存储桶 `irobotbox-hn1`，本次继续沿用。

OSS 访问域名：

https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/

两端已确认的现有 URL 示例：

```text
https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/1/AutoChoose/Production/AI/Generate/20260728/Generate_2eb3768eaad046a79a61dc323a45deb8_415520.JPG
```

该示例按 `YYYYMMDD` 归档，文件名由 `Generate_`、UUID、公共方法追加的六位数字及扩展名组成。该六位数字推测为随机数字，公共方法的具体生成机制尚未确认；本期新文件名不再附加该段。

现有上传流程校验本地图片格式为 jpg/png，扩展名存在 `.jpg`、`.JPG`、`.png`、`.PNG` 等大小写形式。

- 上传时不一定已有任务 ID、系统 SKU 或 ASIN，不能依赖这些字段命名。
- 参考图仅保存 URL，没有独立图片 ID 或 `uniqueId` 数据库字段。
- 上传过程不压缩、不转换图片格式。
- 自动取图、从已有商品图中选图及复制重跑均直接复用原 URL，不重新上传 OSS。

## 需求概述

本期仅统一美工版、运营版新上传参考图的 OSS 路径和文件名，不涉及页面展示调整，不新增参考图图片表、图片 ID 或 `uniqueId` 字段。

直接改造点为参考图上传时的路径、文件名构建及公共上传方法接入；三个上传入口须全部接入并分别回归，不要求每个入口独立实现命名逻辑。复制重跑和取图链路仅回归原 URL 复用行为，不新增上传改造。

| 范围 | 两端实际入口及处理 |
|---|---|
| 上传改造 | 新增任务抽屉、编辑任务抽屉、Tab1「建任务」列表页便捷上传参考图。 |
| 复制重跑回归 | Tab5「已完成」列表页的单个、批量复制重跑按钮；执行后在 Tab1「建任务」列表页创建对应任务，参考图继续引用原 URL。 |
| 取图回归 | 自动取图、从已有商品图中选图，继续直接引用原 URL。 |

## 功能需求

### 1. 新路径及调整原因

```text
https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/1/AiImage/{环境编码}/{业务端}/reference/{YYYY}/{MM}/{DD}/reference-{UUID}.{扩展名}
```

| 调整项 | 具体规则 | 调整原因 |
|---|---|---|
| 域名与一级目录 | 保留现有 OSS 域名及 `/1/`。 | 沿用现有存储位置。 |
| 系统目录 | 使用 `AiImage`，替代原 `AutoChoose` 等系统层级。 | 与生成图统一系统归属。 |
| 环境 | 位于 `AiImage` 后，使用下表中的小写环境编码。 | 集中系统文件，并隔离运行环境。 |
| 业务端 | 美工版为 `aig`，运营版为 `aio`。 | 两端采用相同结构，保留业务区分。 |
| 图片用途 | 固定为 `reference`，与生成图的 `generated` 对称。 | 明确区分参考图与生成结果图。 |
| 日期 | 取实际上传时的北京时间，采用 `YYYY/MM/DD`；年份四位，月、日固定两位，年月日来自同一时间。 | 按年、月、日归档，不依赖任务创建或保存时间。 |
| 模型目录 | 不设置模型目录或子模型目录。 | 参考图不绑定某一次生成使用的模型。 |
| 文件名 | 使用 `reference-{UUID}.{扩展名}`。 | 以 UUID 标识上传对象，文件脱离目录后仍能识别参考图用途。 |

### 2. 环境映射

| 环境编码 | 对应环境 |
|---|---|
| `prod` | 生产环境 |
| `staging` | 预发布环境，上线前验收使用 |
| `test` | 测试环境，日常联调和测试使用 |
| `dev` | 开发环境 |

环境编码由服务端部署配置确定，不由用户选择；枚举不代表新增四套环境。按实际部署用途配置，发布前核对环境与编码的对应关系，与生成图采用相同口径。

### 3. 文件名与扩展名

- 文件名前缀固定为小写 `reference-`；UUID 使用完整的 32 位小写十六进制、无连字符表示形式，不截短，不附加末尾六位数字。
- 不拼接任务 ID、系统 SKU、ASIN、模型或子模型等业务字段；即使上传时未创建任务或未填写商品标识，也可按现有上传流程完成命名。
- 扩展名保留原类型，仅统一小写，例如 `.JPG` → `.jpg`、`.PNG` → `.png`；原本为小写的 `.jpg`、`.png` 保持不变。
- 上传前构建最终路径和文件名，OSS 上传使用的对象名、返回及保存的完整 URL 须对应同一地址；不对完整路径统一转小写。
- 不压缩、不转换图片格式，不改变文件内容；沿用现有 jpg/png 图片格式校验及其他上传校验，不因本期命名调整增加格式支持或改变校验条件。

生产环境命名示例（仅说明结构，不代表已上传文件）：

```text
美工版：
https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/1/AiImage/prod/aig/reference/2026/09/24/reference-2eb3768eaad046a79a61dc323a45deb8.jpg

运营版：
https://irobotbox-hn1.oss-cn-shenzhen.aliyuncs.com/1/AiImage/prod/aio/reference/2026/09/24/reference-ce807fd5e6d94ad595576f08953b65e4.png
```

### 4. 增量生效与 URL 复用

- 上线后通过本期三个上传入口新上传的参考图使用新规则，包括在已有任务中新增上传的参考图。
- 历史参考图文件及已保存 URL 不迁移、不重命名、不改写大小写，不执行专项复制、回填或删除。
- 单个、批量复制重跑均在新任务中复用原参考图 URL；原地址为旧路径、新路径或其他来源地址时，均不为统一命名重新上传或迁移。
- 自动取图及从已有商品图中选图继续直接引用原 URL，不转存到 `reference` 目录。
- 图片后续保存到任务、跨日使用或复制重跑，不重新计算已有 URL 的日期目录；展示及后续生图调用继续使用保存的完整 URL。

### 5. 公共方法与现有业务兼容

新规则仅对本期两端参考图上传链路生效，公共上传方法的其他调用方及生成图路径、文件名不受影响。

发布前核对公共上传方法、访问权限及文件管理逻辑对旧路径前缀和层级的依赖，确保新路径可上传、返回、保存及读取。任务保存、参考图关联、上传失败和重试处理沿用现有机制，不新增状态门槛、重试机制或未保存文件清理规则。

原有账号归属和访问权限不变，不因目录统一扩大图片可见范围。

## 验收标准

美工版、运营版须分别执行以下适用场景；三个上传入口分别验证，不以单个入口通过代替全部入口验收。环境覆盖实际部署的环境，图片格式覆盖现有支持的格式。

| 场景 | 验收要求 |
|---|---|
| 三个入口上传 | 新增任务抽屉、编辑任务抽屉、Tab1 列表页便捷上传均使用新规则；任务可保存，参考图可显示并供后续生图读取；任务、SKU 或 ASIN 尚未具备时，不额外增加上传限制。 |
| 目录与环境 | 两端分别进入 `aig/aio`，部署环境对应正确编码；使用 `reference`，无模型目录；按实际上传的北京时间归档，验证跨日、跨月及月日补零，后续保存任务不改变已有地址。 |
| 文件名 | 前缀为 `reference-`，UUID 为 32 位小写十六进制且无内部连字符；不含旧 `Generate_` 前缀、末尾六位数字或任务、商品、模型字段。 |
| 扩展名与内容 | 分别验证 `.jpg`、`.JPG`、`.png`、`.PNG` 输入，上传后的扩展名对应为 `.jpg`、`.png`，格式校验沿用现有规则；文件内容与上传前一致，未压缩或转换；实际对象地址与返回、保存的 URL 完全对应。 |
| 历史及复制重跑 | 历史地址不变且仍可使用；已有任务中新上传图片采用新规则；Tab5 单个、批量复制重跑后在 Tab1 创建对应任务，参考图 URL 与源任务完全一致，不新增文件转存。分别覆盖旧、新路径参考图。 |
| 自动及已有图选取 | 自动取图、从已有商品图中选图后，保存和使用的 URL 与来源地址一致，不因本期规则重新上传。 |
| 失败与业务兼容 | 原有校验不通过、上传失败及重试场景沿用现有提示和处理机制；任务与参考图关联不串任务，不因本期调整改变失败处理或文件内容。 |
| 隔离与公共调用 | 两端及原有账号有权、无权访问场景分别回归，不扩大图片可见范围；生成图和公共上传方法其他调用方的路径及文件名不变。 |
